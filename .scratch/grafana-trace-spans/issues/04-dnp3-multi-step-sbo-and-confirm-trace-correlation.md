# 04: DNP3 Multi-Step Trace Correlation (Select-Before-Operate & Application Confirm)

**What to build:** Connect multi-step DNP3 protocol handshakes into streaming-safe parent/child trace hierarchies driven exclusively by the **Virtual Clock**, with zero retroactive database updates across flushed batches.

For **Select-Before-Operate (SBO)** control sequences, `Select` (`FC 0x03`) acts as the root span and a subsequent `Operate` (`FC 0x04`) targeting the same `(DevicePairId, TargetAddress)` within the configured **SBO Window** (`sbo_window_ms`) attaches as its child span sharing the same **Trace ID**. For **Application Confirm (`FC 0x00`)**, any solicited (`FC 0x81`) or unsolicited (`FC 0x82`) response with `CON = 1` tracks a pending confirmation; when the Master sends `FC 0x00`, a child `Confirm` span measures confirm turnaround latency, and if confirmation never arrives within `timeout_threshold_ms` (or before EOF), a child `ConfirmTimeout` error span surfaces the unconfirmed response in Grafana Trace View.

**Blocked by:** 03: DNP3 Solicited, Unsolicited, Direct-No-Ack & Edge-Case Trace Spans

**Status:** resolved

- [x] A DNP3 `Select` (`FC 0x03`) request targeting a CROB `TargetAddress` registers an active SBO entry keyed by `(DevicePairId, TargetAddress)` holding `(SelectTraceId, SelectSpanId, AnchorUtc = requestTimestamp)` and refreshes `AnchorUtc = responseTimestamp` upon successful `FC 0x81` response; entries are cleared if the `Select` fails with an IIN error or times out, and stale entries older than `TestSession.SboWindowMs` are pruned during Virtual Clock `FlushExpiredTimeouts` sweeps.
- [x] When a DNP3 `Operate` (`FC 0x04`) request arrives for the same `(DevicePairId, TargetAddress)` within `sbo_window_ms`, it consumes the pending SBO entry, inherits `TraceId = SelectTraceId`, sets `ParentSpanId = SelectSpanId` with a fresh deterministic `SpanId` (`SpanCorrelationRole.SboOperate`), sets `dnp3.sbo_linked = true`, and stamps the inherited `TraceId` and child `SpanId` onto its `ProtocolTransactionRecord`, `CapturedCommandEventRecord`, and `ExtractedDataPointRecord` outputs.
- [x] When an `Operate` (`FC 0x04`) arrives with no active matching SBO entry (or after `sbo_window_ms` has elapsed), it starts an independent root trace (`ParentSpanId = null`) and records `dnp3.sbo_linked = false`.
- [x] Any `ServerToClient` DNP3 response (`FC 0x81` solicited—including orphan `FC 0x81`—or `FC 0x82` unsolicited) with `CON == true` registers a pending confirm entry keyed by `(DevicePairId, AppSeq, IsUnsolicited)` ordered by Virtual Clock `ResponseTimestampUtc` (when `StoreTraceSpans == true`).
- [x] When a `ClientToServer` Master Application Confirm (`FC 0x00`) arrives, it matches the pending confirm by `(DevicePairId, AppSeq, UNS)` (falling back to `(DevicePairId, AppSeq)`), emits a child `Confirm` span (`TraceId = pending.TraceId`, `ParentSpanId = pending.SpanId`, `OperationName = "DNP3 FC00 Confirm"`, `ServiceName = ServerEndpoint`, `SpanKind = Client`, `StartTime = pending.ResponseTimestampUtc`, `EndTime = confirmFrame.TimestampUtc`, `DurationMs = confirm - response`, `StatusCode = Ok`, `ConfirmSent` event), and does not emit a `ProtocolTransactionRecord`.
- [x] An unmatched `FC 0x00` Confirm (no pending confirm entry) emits a zero-duration standalone `Confirm` span with `StatusCode = Unset` and `protocol.unpaired = true`.
- [x] During `FlushExpiredTimeouts(currentVirtualTime, isEndOfFile)`, any pending confirm exceeding `timeout_threshold_ms` (or remaining at EOF) is dequeued and emits a child `ConfirmTimeout` error span (`TraceId = pending.TraceId`, `ParentSpanId = pending.SpanId`, `OperationName = "DNP3 FC00 Confirm"`, `StatusCode = Error`, `StatusMessage = "CONFIRM_TIMEOUT"` or `"CONFIRM_TIMEOUT_AT_EOF"`, `DurationMs = timeoutThresholdMs` or elapsed to EOF, `ConfirmTimeoutExpired` event) in `TimeoutFlushOutput.TraceSpans` without emitting a `ProtocolTransactionRecord`.
- [x] When `StoreTraceSpans` is `false`, SBO and Confirm tracking buffers remain inactive and emit zero spans.
- [x] Unit tests thoroughly verify SBO linking within window, SBO window expiry, mismatched `TargetAddress` isolation, failed/timed-out `Select` cleanup, solicited and unsolicited `CON=1` confirm nesting (including full `Select → Confirm → Operate → Confirm` trees), orphan confirms, and mid-stream + EOF `ConfirmTimeout` spans strictly under Virtual Clock timestamps.
