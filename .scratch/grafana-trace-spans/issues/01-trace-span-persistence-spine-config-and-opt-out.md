# 01: End-to-End Trace Span Persistence Spine, Configuration & Opt-Out

**What to build:** Stand up the complete vertical ingestion and persistence spine for OpenTelemetry/W3C-compatible **Trace Spans**—from session manifest configuration and CLI options, through pure core domain models, Virtual Clock timeout handling, and pipeline batching, down into TimescaleDB—so downstream protocol decoders can emit correlated spans without touching schema or plumbing.

Operators can optionally declare human-readable **Device Endpoint Names** (`client_name`, `server_name`), configure the DNP3 **SBO Window** (`sbo_window_ms`, default `10000`), and toggle span persistence (`store_trace_spans`, default `true`, overridable via CLI `--no-traces`). Existing manifests omitting these fields continue to parse unchanged with backward-compatible defaults. All core domain types remain free of database, `tshark`, and OpenTelemetry SDK dependencies, and all timing remains driven strictly by the **Virtual Clock**.

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] Strong domain value objects `TraceId` (32 lowercase hex chars, non-zero) and `SpanId` (16 lowercase hex chars, non-zero) validate inputs via `Parse`/`TryParse`, and `DeterministicTraceIdGenerator` derives repeatable W3C IDs via BCL `SHA256` from `(SessionId, DevicePairId, FrameNumber, Role[, Disambiguator])` with a non-zero guard.
- [x] Strong domain enums (`SpanKind`, `SpanStatusCode`, `SpanOriginKind`, `SpanCorrelationRole`, `SpanEventKind`) and records (`TraceSpanRecord`, `SpanEventRecord`, `PendingSpanContext`, `TimeoutFlushOutput`) are defined in the core domain with zero external NuGet dependencies.
- [x] Existing domain records are extended in a backward-compatible way: `TestSession` gains `StoreTraceSpans = true` and `SboWindowMs = 10000`; `DeviceEndpointPair` gains optional `ClientName`/`ServerName` plus pure `ResolveClientEndpoint()` and `ResolveServerEndpoint()` helpers (`Name` → `IP:ProtocolAddressId` → `IP`); `ProtocolTransactionRecord`, `ExtractedDataPointRecord`, and `CapturedCommandEventRecord` gain nullable `TraceId` and `SpanId`; `ProtocolDecodeOutput` includes `TraceSpans`; `PipelineExecutionSummary` tracks `TraceSpansPersisted`.
- [x] `IProtocolDecoder.FlushExpiredTimeouts` returns `TimeoutFlushOutput` (both timed-out RED transactions and timed-out `TraceSpanRecord`s), and `VirtualClockRedEngine` propagates an optional `PendingSpanContext` from `RegisterRequest` into both `TryCompleteResponse` and mid-stream/EOF timeout sweeps using Virtual Clock timestamps only.
- [x] Existing Modbus TCP and DNP3 decoders compile and pass all existing tests against the updated `FlushExpiredTimeouts` contract (emitting empty span lists until their dedicated tickets land).
- [x] `ManifestParser` parses `store_trace_spans` (default `true`), `sbo_window_ms` (default `10000`, throwing `FormatException` when `<= 0`), and optional trimmed `client_name`/`server_name`; CLI `analyze` accepts `--no-traces`, overrides `TestSession.StoreTraceSpans = false` prior to session initialization when passed, and prints `Trace spans persisted` in the completion summary when tracing is enabled.
- [x] An idempotent incremental TimescaleDB migration (`002_add_trace_spans.sql`) adds `store_trace_spans` and `sbo_window_ms` to `test_sessions`, `client_name` and `server_name` to `device_pairs`, nullable `trace_id`/`span_id` columns plus partial indexes to `red_transactions`, `captured_command_events`, and `tag_values`, and creates the `trace_spans` 1-day hypertable (`ON DELETE CASCADE` to `test_sessions` and `device_pairs`) with its session/trace/error/device-pair indexes; Docker Compose mounts the SQL initialization directory so fresh setups apply `001` then `002` automatically.
- [x] The persistence seam serializes all new domain enums and JSONB `attributes`/`events` (Grafana Trace `logs` shape) cleanly via binary `COPY` in `TimescaleDbBatchSink`, and `IngestionPipelineOrchestrator` buffers and flushes `TraceSpanRecord` batches (skipping span persistence when `StoreTraceSpans` is `false`).
- [x] Unit tests across Core, Infrastructure, and CLI verify deterministic IDs, endpoint name fallbacks, Virtual Clock timeout span emission, manifest parsing, `--no-traces` opt-out, and binary `COPY` column mapping without external binaries; live integration tests verify `002_add_trace_spans.sql` idempotency and `delete_test_session(UUID)` cascade cleanup across `trace_spans`.
